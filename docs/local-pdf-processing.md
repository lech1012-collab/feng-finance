# Local PDF processing

Feng validates PDF magic, extension, file size (30 MB) and page count (100). A
SHA-256 hash identifies an exact reimport. The source file and PDF.js document
remain in memory during the import review; neither is uploaded or saved to
IndexedDB by this pipeline.

Embedded text is preferred. `extractEmbeddedPage` converts positioned PDF text
into scale-1 viewport rectangles with a top-left origin and records font size,
page number and `parseSource: text`. Page geometry includes empty pages. The
generic quality check decides which pages need image reading. A text-layer
decoder failure also sends that page to local OCR rather than accepting partial
decoded words. Existing bank-parser compatibility wrappers retain their baseline
coordinate convention.

Whole-page and numeric-cell OCR render at 300 DPI, bounded to 18 million pixels.
Cell OCR uses only `0123456789,.-()` and single-line segmentation. It produces
alternatives, not accepted financial corrections: the parser must independently
prove that a replacement balances exactly before selecting it. OCR-derived words
have explicit source metadata and an internal confidence no higher than 0.6.

The main thread renders one canvas at a time. A small module worker receives
transferable PNG bytes and owns Tesseract's nested worker. Its parent can be
terminated while Tesseract is initializing, recognizing a page, or reading a
cell. This avoids relying on the Tesseract `createWorker()` promise, which exposes
its worker only after initialization. Workers load JavaScript, WebAssembly and
English language data from bundled, base-relative, same-origin URLs.

Cancellation keeps only complete pages and explicitly returns every unread page
number. Tesseract's progress fraction of 1 is not treated as completion: a
separate `completed` progress marker follows a retained result. A cancelled
extraction remains available for local review crops until the import is discarded
or confirmed. `PdfImportSession.dispose()` is idempotent; it cancels active jobs,
rejects queued jobs, releases the PDF document and file, and clears raw text,
geometry and quality arrays. UI code owns and must revoke crop object URLs.

No filenames, OCR exceptions, images, statement words or numeric values are sent
to external services. The worker returns an allowlisted word/bounding-box shape
and replaces library failure strings with actionable generic errors. OCR language
cache entries contain the public language model, not statement images or text.

PDF-engine verification on 11 October 2026 used an isolated harness and fictitious
image-only PDF fixtures with no embedded text. Under the production Content
Security Policy, both Chromium and WebKit completed whole-page OCR, a numeric-cell
reading, a review crop and a two-page cancellation retaining page one and marking
page two unread. The harness waited for its complete app/OCR asset cache and then
shut down its HTTP origin before processing. All subsequent requests were GETs for
same-origin assets; there were no third-party requests, financial payload requests
or browser errors. The complete application workflow is separately covered by
`tests/e2e/v22-pdf-ocr.spec.ts`, including import review, explicit acceptance of
unread pages, persistent transaction metadata and one-penny discrepancy correction.
Focused tests also cover cancellation during worker initialization, invalid crop
bounds, canvas cleanup, aborted PDF loading, rejected recognition and queued-job
disposal. Actual iPhone installation and OCR performance remain real-device
checks; desktop browser timings do not establish the iPhone-12 targets.

Synthetic OCR fixtures are generated by `scripts/ocr-fixtures.mjs`. Real statements
must stay in ignored private fixture locations and must never be committed.
The generator also creates a readable page with an unusable embedded-text layer
(`ocr-garbled.pdf`) and a digital statement whose amount differs from its running
balance by one penny (`generic-one-penny.pdf`). Neither fixture contains personal
information. A one-penny difference is a warning under the v2.2 exact policy.
